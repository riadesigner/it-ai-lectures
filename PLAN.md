## Лекция 1. Что такое prompt-инжиниринг и зачем он гейм-дизайнеру

**Цель:** снять мифы об ИИ, показать место prompt-инжиниринга в пайплайне разработки игр.


| Блок               | Время  | Содержание                                                                                                                     |
| ------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| Знакомство         | 10 мин | Цели курса, правила, ожидания, этика использования ИИ в учёбе                                                                  |
| Контекст индустрии | 25 мин | Где ИИ уже применяют в gamedev: Ubisoft Ghostwriter, NPC-диалоги, концепт-арт, QA, генерация текста и квестов через LLM; что ИИ **не** заменяет (классический PCG без ИИ — отдельная тема) |
| Базовые понятия    | 30 мин | LLM, промпт, контекст, токены, галлюцинации, temperature (интуитивно); разница «чат» vs «инструмент»                           |
| Демонстрация       | 20 мин | Live-demo: один и тот же запрос — плохой vs хороший промпт для описания игрового мира                                          |
| Q&A                | 5 мин  | Вопросы, домашнее задание                                                                                                      |


**Ключевые тезисы:**

- Prompt-инжиниринг — навык формулировки задачи, а не «магические слова».
- ИИ — ассистент дизайнера, финальное решение остаётся за человеком.

**Домашнее задание:** найти 2 примера использования ИИ в играх (новость, кейс, интервью) и кратко описать, какую задачу решали.

## Практика 1. Первый контакт: регистрация, интерфейс, первые промпты

**Цель:** каждый студент самостоятельно получает результат от LLM и фиксирует наблюдения.


| Этап       | Время  | Задание                                                                                           |
| ---------- | ------ | ------------------------------------------------------------------------------------------------- |
| Настройка  | 15 мин | Регистрация / вход в выбранный LLM, знакомство с интерфейсом                                      |
| Разминка   | 20 мин | 3 простых промпта: «опиши жанр», «придумай название игры», «опиши главного героя» — без структуры |
| Сравнение  | 25 мин | Повторить те же задачи с добавлением контекста (жанр, платформа, аудитория, референсы)            |
| Рефлексия  | 25 мин | Заполнить таблицу: промпт → результат → что улучшить → улучшенный промпт                          |
| Обсуждение | 5 мин  | 2–3 студента делятся лучшим и худшим результатом                                                  |


**Результат занятия:** документ «Мои первые 6 промптов» (3 плохих + 3 улучшенных).

## Лекция 2. Анатомия промпта: из хаоса в структуру

**Цель:** дать универсальный шаблон промпта и показать его на игровых задачах.


| Блок             | Время  | Содержание                                                                                                     |
| ---------------- | ------ | -------------------------------------------------------------------------------------------------------------- |
| Разбор структуры | 30 мин | **RCTF**: Role (роль) → Context (контекст) → Task (задача) → Format (формат ответа); Constraints (ограничения) |
| Примеры          | 25 мин | Промпт для описания локации, промпт для игровой механики, промпт для UI-текста                                 |
| Типы промптов    | 20 мин | Zero-shot, one-shot, few-shot; когда показывать примеры                                                        |
| Типичные ошибки  | 10 мин | Слишком расплывчато, противоречивые инструкции, перегруз контекстом                                            |
| Q&A              | 5 мин  |                                                                                                                |


**Шаблон для студентов:**

```
Role: Ты — опытный гейм-дизайнер [жанр].
Context: Мы делаем [игра, платформа, аудитория, референсы].
Task: [конкретная задача].
Format: [список / таблица / JSON / абзацы].
Constraints: [лимит слов, тон, что нельзя].
```

**Домашнее задание:** переписать 3 промпта из практики 1 по шаблону RCTF.

## Практика 2. Мастерская структуры: от плохого промпта к рабочему

**Цель:** отработать RCTF на типовых задачах гейм-дизайнера.


| Этап         | Время  | Задание                                                                                   |
| ------------ | ------ | ----------------------------------------------------------------------------------------- |
| Разбор       | 10 мин | Преподаватель разбирает 3 «убийцы промптов» из реальной практики                          |
| Сolo-work    | 35 мин | Студент получает 5 заведомо плохих промптов → переписывает по RCTF → генерирует результат |
| Пairs        | 30 мин | Обмен промптами с соседом: «прогони мой промпт, дай фидбек»                               |
| Мини-конкурс | 10 мин | Лучший промпт для задачи «опиши систему крафта в survival-игре»                           |
| Итог         | 5 мин  | Сохранить 5 финальных промптов в личную библиотеку                                        |


**Результат занятия:** 5 отработанных промптов в библиотеке + 1 peer-review комментарий.

## Практика 3. Лаборатория итераций

**Цель:** освоить цикл улучшения на одной сквозной задаче.


| Этап         | Время  | Задание                                                                                      |
| ------------ | ------ | -------------------------------------------------------------------------------------------- |
| Бриф         | 10 мин | Задача: «Side-quest для RPG на 15–20 минут геймплея»                                         |
| Итерация 1–2 | 25 мин | Первый промпт → оценка по чеклисту (оригинальность, ясность, связь с механиками) → доработка |
| Итерация 3–4 | 25 мин | Добавить CoT: «сначала цель квеста, потом шаги, потом награда, потом edge cases»             |
| A/B тест     | 20 мин | Два разных промпта на одну задачу — сравнительная таблица                                    |
| Презентация  | 10 мин | 3 студента показывают эволюцию своего квеста (промпт v1 → v4)                                |


**Чеклист оценки результата:**

- [ ] Понятна мотивация игрока
- [ ] Есть игровая механика, не только текст
- [ ] Награда сбалансирована
- [ ] Нет логических дыр
- [ ] Стиль соответствует сеттингу

**Результат занятия:** quest design doc (1 стр.) + лог из 4+ итераций промптов.

## Практика 7. Мини-GDD за полтора часа

**Цель:** собрать документ, где каждая секция создана с помощью промптов и отредактирована вручную.


| Этап         | Время  | Задание                                                                                                        |
| ------------ | ------ | -------------------------------------------------------------------------------------------------------------- |
| Концепт      | 10 мин | Elevator pitch (1 предложение) + 3 design pillars                                                              |
| GDD sections | 50 мин | Заполнить по промптам: Overview, Target Audience, Core Loop, Key Features, Art Direction, 1 Quest, 1 Character |
| QA pass      | 20 мин | Промпт-критик: «найди пробелы, противоречия, слабые места» → правки                                            |
| Peer review  | 10 мин | Обмен GDD с соседом по чеклисту                                                                                |


**Чеклист GDD:**

- [ ] Pillars согласованы с mechanics
- [ ] Core loop описан actionable
- [ ] Art direction связан с mood board
- [ ] Нет «generic» формулировок без правки
- [ ] Указано, где использовался ИИ

**Результат занятия:** Mini-GDD (3–5 стр.) — черновик итогового проекта.

## Лекция 8. Продвинутые техники и будущее ИИ в gamedev

**Цель:** дать инструменты для самостоятельного развития и обозначить тренды.


| Блок                 | Время  | Содержание                                                                    |
| -------------------- | ------ | ----------------------------------------------------------------------------- |
| System prompts       | 20 мин | Custom instructions, project-level context, «персона» ассистента для проекта  |
| Multi-step workflows | 20 мин | Цепочки промптов: idea → outline → draft → critique → final; agent-like flows |
| Structured output    | 15 мин | JSON, markdown tables, YAML — промпты для машиночитаемых форматов             |
| Tooling overview     | 15 мин | Cursor, Copilot, in-engine AI (обзор); что изучать дальше                     |
| Trends               | 10 мин | Real-time NPC, procedural narrative, AI playtesting — что ждёт индустрию      |
| Итоговый проект      | 5 мин  | Требования, дедлайн, критерии оценки                                          |
| Q&A                  | 5 мин  |                                                                               |


**Требования к итоговому проекту:**

1. Игровая концепция (1 абзац)
2. Библиотека из **15+ промптов** с категориями (world, character, quest, mechanics, visual, GDD)
3. **3 финальных артефакта**, созданных через итерации (world bible, quest, character или mechanics doc)
4. Рефлексия (½ стр.): что сработало, что нет, этические выводы

| Рефлексия   | 5 мин  | Индивидуально: 3 навыка, которые заберу в проектную работу                  |
