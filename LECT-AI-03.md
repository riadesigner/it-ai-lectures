## Что такое шаблон промпта

**Короткий ответ**

**Шаблон промпта (prompt template)** — заготовка с переменными, которую можно многократно заполнять разными данными. После подстановки получается **экземпляр промпта (instance)** — конкретный запрос, который отправляют в модель.

Сам **промпт** шире: любая инструкция для генеративной модели (текст, изображение, видео; почти всегда с текстовой частью). Шаблон нужен, когда одну и ту же задачу решают много раз с разным входом.

Шаблон – как **инструмент мышления**: он помогает вам ничего не забыть и четко сформулировать задачу.

**Пример шаблона (для анализа тональности):**

```
Ты — профессиональный фитнес-тренер. 
Составь план тренировок для [ЦЕЛЬ: похудение / набор массы / поддержка тонуса].
Уровень подготовки: [НАЧАЛЬНЫЙ / СРЕДНИЙ / ПРОДВИНУТЫЙ].
Доступный инвентарь: [СПИСОК].
Количество тренировок в неделю: [ЧИСЛО].

Ответ дай в виде списка по дням недели. 
Каждое упражнение опиши в 1 предложении. 
Общая длительность одной тренировки — не более [ВРЕМЯ] минут.
```

Для каждого поста из датасета создаётся свой экземпляр и отправляется в модель.

**На курсе:** промпт = ТЗ для модели; шаблон = форма, которую вы заполняете под разные квесты, NPC, таблицы баланса.

## Компоненты промпта

**Короткий ответ**

В разных источниках компоненты называют по-разному. Ниже — универсальный набор из статьи:


| Компонент               | Англ.                  | Что это                                                                                                                          |
| ----------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Роль**                | Role / Persona         | Кем «быть» модели: «narrative designer», «баланс-дизайнер»                                                                       |
| **Директива / Задача**  | Directive / Task       | Задача: инструкция или вопрос. Может быть явной («Посоветуй 5 книг») или имплицитной (только пример: `Night: Noche; Morning: ?`) |
| **Примеры**             | Examples / Shots       | Образцы выполнения задачи (one-shot, few-shot)                                                                                   |
| **Формат выдачи**       | Output Formatting      | Как оформить ответ: CSV, Markdown, JSON, таблица                                                                                 |
| **Инструкции по стилю** | Style Instructions     | Тон, лаконичность, жанр: «без повторов», «мрачный тон»                                                                           |
| **Доп. информация**     | Additional Information | Факты для задачи: имена, должности, сеттинг, ограничения проекта                                                                 |


**Связь с RCTF (лекция 2):** Role → R, Additional Information → C, Directive → T, Output Formatting → F, Style + ограничения → Constraints.

**Частая ошибка:** дать только директиву («придумай квест») без формата и контекста — ответ будет размытым.

## Промптинг и промпт-инжиниринг

**Короткий ответ**

Термины часто путают. Различия:


| Термин                         | Смысл                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| **Промптинг**                  | Любое взаимодействие с моделью через промпты (один запрос или серия)                   |
| **Цепочка промптов**           | Несколько шаблонов **последовательно**: ответ на первый → вход для второго             |
| **Техника промптинга**         | «Схема» построения промпта или цепочки (последовательно, с ветвлением или параллельно) |
| **Промпт-инжиниринг**          | **Итеративный** поиск лучшего промпта: тест → оценка → правка шаблона                  |
| **Техника промпт-инжинирингa** | Стратегия улучшения промпта (вручную или автоматически)                                |


**Цикл промпт-инжиниринга (3 шага):**

1. Прогнать промпт на наборе примеров (тестовые квесты, NPC-реплики).
2. Оценить качество (формат, лор, играбельность).
3. Отредактировать шаблон и повторить.

**Аналогия:** промптинг — разговор с моделью; промпт-инжиниринг — отладка рецепта, пока блюдо стабильно получается.

**На курсе:** практики 2–3 — именно инжиниринг: A/B промптов, итерация по RCTF, не «один раз спросил и сдал».

## Текстовые техники промпта

**Короткий ответ**

**Текстовые техники промпта** — способы построить промпт (или цепочку промптов), чтобы модель лучше справилась с задачей. В обзоре *The Prompt Report* их делят на **6 категорий**:

1. **Few-Shot**
2. **Zero-Shot**
3. **Chain-of-Thought**
4. **Ensembling**
5. **Self-Criticism**
6. **Decomposition**

В этой лекции разбираем **few-shot** и **zero-shot**; остальные категории — в следующих частях цикла. Всего упоминаются [58 техник](accessories/ai-prompts-technics.png).

## Контекстное обучение (ICL)

**Короткий ответ**

**In-Context Learning (ICL)** — модель «подстраивается» под задачу **без обновления весов**, только за счёт примеров и инструкций в промпте.

Важно: «новая задача» не значит, что модель никогда не видела похожих паттернов — скорее, нужна **конкретная инструкция**, чтобы активировать нужное поведение.

**Смежный термин:** **meta-learning** — шире: обучение модели быстро адаптироваться к разным типам задач на этапе pre-training. ICL — про адаптацию **в одном запросе**.

**Для gamedev:** few-shot = показать 2–3 образца диалога NPC в нужном тоне; zero-shot = только инструкция «пиши как смотритель маяка».

## Few-shot промптинг

**Короткий ответ**

**Few-shot** — в промпт добавляют **несколько примеров** «вход → выход», чтобы модель уловила закономерность. Это разновидность few-shot learning, но **без дообучения** модели.

**Базовый шаблон:**

```
Пример 1: {вход} → {выход}
Пример 2: {вход} → {выход}
Задача: {тестовый вход} → ?
```



## Принципы отбора few-shot примеров

**Короткий ответ**

Шесть принципов из статьи (не универсальны — проверять на своей задаче):


| #   | Принцип                 | Суть                                                                                                                        |
| --- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Количество**          | Больше примеров → часто лучше; но >20 может не помочь или ухудшить (особенно у малых моделей)                               |
| 2   | **Порядок**             | Перестановка примеров может сильно менять точность (до 50% → 90% в исследованиях)                                           |
| 3   | **Распределение меток** | Перекос (8 позитивных / 2 негативных) → модель отвечает предвзято                                                           |
| 4   | **Качество меток**      | Спорно, влияет ли ошибка в примере; крупные модели устойчивее к шуму                                                        |
| 5   | **Формат**              | Единый формат (`Q: … A: …`); лучше ближе к тому, как данные выглядели при обучении модели                                   |
| 6   | **Инструкция**          | Во few-shot иногда **достаточно только примеров**; лишняя конкретная инструкция может **снизить** качество на классификации |


**Для gamedev:** если few-shot — три реплики NPC, держите один тон, одну длину строки и баланс «вопрос / ответ»; не смешивайте комедию и трагедию в примерах без причины.

**Частая ошибка:** скопировать 10 примеров «как попало» и удивиться нестабильному результату.

## Zero-shot промптинг

**Короткий ответ**

**Zero-shot** — **без примеров** в промпте, только инструкция (и при необходимости роль, стиль, контекст). Базовые приёмы zero-shot разбираются ниже; комбинации с Chain-of-Thought — в части 2 цикла на Habr.

**Когда zero-shot:** быстрый черновик, широкая задача, нет готовых эталонных примеров. **Когда few-shot:** нужен строгий формат, тон или классификация по образцу.

## Zero-shot техники: краткий справочник

**Короткий ответ**

Основные техники из части 1:


| Техника                        | Что делать                                                     | Зачем                                               |
| ------------------------------ | -------------------------------------------------------------- | --------------------------------------------------- |
| **Role / Persona Prompting**   | «Ты — narrative designer indie-RPG…»                           | Лучше открытые ответы, спец. знания, единый тон     |
| **Style Prompting**            | Задать стиль, тон, жанр                                        | Лаконичность, мрачность, юмор без смены роли        |
| **Emotion Prompting**          | Психологические триггеры («Это важно для моей карьеры»)        | Иногда повышает вовлечённость модели в задачу       |
| **S2A** (System 2 Attention)   | Сначала попросить **очистить промпт** от лишнего, потом ответ  | Меньше шума в длинном контексте                     |
| **SimToM**                     | Двухшагово: «Что знает персонаж X?» → ответ с его точки зрения | Задачи с несколькими агентами и ложными убеждениями |
| **RaR** (Rephrase and Respond) | «Перефразируй и уточни вопрос, затем ответь»                   | Модель сама уточняет неясный запрос                 |
| **RE2** (Re-reading)           | Добавить «Ещё раз прочитай вопрос»                             | Внимательнее к формулировке                         |
| **Self-Ask**                   | Модель задаёт себе уточняющие вопросы, отвечает, потом финал   | Глубже проработка сложного брифа                    |


**Пример SimToM (из статьи):** «Джим положил мяч в коробку. Ави переложил в корзину. Где мяч **по мнению Джима**?» — сначала шаг «Что знает Джим?», потом ответ (не путать с фактическим положением мяча).

**Для gamedev:**

- **Role** — «ты гейм-дизайнер roguelike на мобилках»;
- **Style** — «реплики по 1 предложению, без modern сленга»;
- **SimToM** — диалоги NPC, которые **не знают** событий, произошедших off-screen;
- **RaR / Self-Ask** — размытый бриф от продюсера: модель сначала уточняет scope.

**Что дальше (части 2–5 на Habr):** Chain-of-Thought, декомпозиция, ансамбли; мультимодальность; агенты; галлюцинации и prompt injection.
