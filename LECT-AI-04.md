## Что такое Chain-of-Thought (CoT)

**Короткий ответ**

**Chain-of-Thought (CoT, «цепочка рассуждений»)** — техника промптинга, при которой модель не только выдаёт ответ, но и **показывает ход рассуждения** (*Thought Generation*).

Как правило, в промпт добавляют один или несколько **примеров рассуждения**, затем дают аналогичную задачу и просят решить её **вместе с объяснением шагов**. Это заметно повышает качество на **математических и логических** задачах.

**Пример (one-shot CoT):**

```
Задача: У Джека две корзины, в каждой по 3 мяча. Сколько всего мячей?
Рассуждение: В одной корзине 3 мяча, в двух — 2 × 3 = 6 мячей.
Ответ: 6.

Задача: [новая аналогичная задача]
Рассуждение: ...
```

**На курсе:** CoT — «покажи черновик дизайна», а не только финальный квест; полезно для баланса, условий победы, логики головоломок.

## Zero-Shot CoT и вариации без примеров

**Короткий ответ**

**Zero-Shot CoT** — CoT **без примеров**: в промпт добавляют **триггерную фразу**, которая запускает пошаговое рассуждение.


| Техника                      | Что делать                                                                                       | Зачем                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **Zero-Shot CoT**            | «Рассуждай шаг за шагом» / «Сначала подумай логически»                                           | Не нужны примеры; работает на любой задаче                                                    |
| **Step-Back Prompting**      | Сначала наводящий вопрос о **общих принципах** (закон, формула), потом решение                   | Активирует нужные знания; лучше обычного CoT на физике и т.п.                                 |
| **Analogical Prompting**     | Попросить модель **вспомнить аналогичные задачи** из обучающих данных, затем решить новую        | Синтетические примеры рассуждений; хорошо для математики и кода                               |
| **Thread-of-Thought (ThoT)** | Развёрнутый триггер: «Проанализируй всю информацию, пошагово объясни, при необходимости обобщай» | Вопросы с большим контекстом, RAG, информационный поиск                                       |
| **Tabular CoT (Tab-CoT)**    | Инструкция оформить рассуждение **таблицей Markdown**                                            | Структура при многоступенчатых условиях; меньше токенов (≈140 → ≈28 слов в примере из статьи) |


**Пример Step-Back:** перед задачей по физике — «Какой физический закон нужен?» → модель вспоминает уравнение идеального газа → считает ответ. Обычный «шаг за шагом» в том же примере может дать ошибку.

**Пример эмоционального триггера:** «Рассуждай шаг за шагом, **чтобы не допустить ошибку**».

**Для gamedev:** ThoT + длинный лор-документ; Tab-CoT — таблица «условие → эффект → баланс» для механик.

## Few-Shot CoT и вариации с примерами

**Короткий ответ**

**Few-Shot CoT** — модель получает **несколько примеров** полного рассуждения. Если примеры написаны человеком, технику также называют **Manual CoT** или **Golden CoT**.


| Техника             | Суть                                                         | Когда помогает                      |
| ------------------- | ------------------------------------------------------------ | ----------------------------------- |
| **Contrastive CoT** | В промпт — **правильные и неправильные** примеры рассуждения | Арифметика, фактологические вопросы |


**Для gamedev:** Contrastive CoT — показать «плохой» и «хороший» дизайн квеста.

## Что такое декомпозиция в промптинге

**Короткий ответ**

**Декомпозиция (Decomposition)** — разбиение **сложной задачи на подзадачи**. Часть техник похожа на CoT (модель сама «дробит» задачу), но если **пользователь** заранее разбивает инструкцию на простые шаги, качество часто **ещё выше**.

CoT и декомпозиция — соседние категории в *The Prompt Report* (категории 3 и 6 из шести).

**Аналогия:** CoT — модель ведёт черновик; декомпозиция — вы сами составили план уровня, модель заполняет этапы.

## Техники декомпозиции: обзор

**Короткий ответ**

Сначала план, потом решение    


| Техника                     | Как работает                                                                                       | Особенности                                                          |
| --------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **Least-to-Most**           | Сначала разбить на подзадачи → решать **по очереди**, добавляя ответы в промпт                     | Символьные преобразования, обобщение (саммари)                       |
| **Plan-and-Solve**          | «Сначала план, потом выполни план шаг за шагом» — улучшенный zero-shot CoT                         | Меньше логических ошибок                                             |
| **Tree-of-Thought (ToT)**   | **Дерево** вариантов: несколько первых шагов → выбор лучшего → ветвление дальше                    | Планирование, стратегии                                              |
| **Recursion-of-Thought**    | Сложная подзадача уходит в **отдельный промпт** (или другую модель), результат вставляется обратно | Обход лимита контекста; часто нужен спец. токен или текстовый аналог |
| **Faithful CoT**            | Параллельно: рассуждение на **естественном языке** + **код**                                       | NL-инструкция → функция → исполнение                                 |
| **Skeleton-of-Thought**     | «Скелет» подзадач → **параллельная** обработка → сборка ответа                                     | Быстрее последовательного CoT                                        |
| **Metacognitive Prompting** | Пять этапов как у человека: уточнение → черновик → оценка → стратегия → уверенность                | Самопроверка и рефлексия                                             |


**Metacognitive Prompting — пять шагов в промпте:**

1. Уточнить вопрос.
2. Первичное решение.
3. Оценить первичное решение.
4. Выбрать итоговую стратегию.
5. Оценить уверенность.

**Для gamedev:** Least-to-Most — «сначала механика, потом UI, потом баланс»; ToT — ветвящийся сюжет; Skeleton-of-Thought — параллельная генерация веток диалога по пунктам плана.

## CoT vs декомпозиция: когда что использовать

**Короткий ответ**


| Ситуация                                                | Что попробовать                                  |
| ------------------------------------------------------- | ------------------------------------------------ |
| Одна логическая/математическая задача, нужен ход мыслей | **Zero-Shot CoT** или **Few-Shot CoT**           |
| Нужны общие принципы перед расчётом                     | **Step-Back**                                    |
| Много контекста, RAG, длинный документ                  | **Thread-of-Thought**, **Tab-CoT**               |
| Сложная многошаговая инструкция                         | **Least-to-Most**, **Plan-and-Solve**            |
| Планирование с ветвлениями                              | **Tree-of-Thought**                              |
| Очень длинная цепочка, лимит контекста                  | **Recursion-of-Thought**                         |
| Самопроверка ответа                                     | **Metacognitive Prompting**, **Contrastive CoT** |


**Частая ошибка:** только «рассуждай шаг за шагом» на задаче с неявными зависимостями между шагами — лучше явный **план** (Plan-and-Solve) или **разбиение** (Least-to-Most).
